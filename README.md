- **Project:** Doctor Appointment Management System

A REST API that lets a medical centre book consultations online. An **outpatient** books a
**consultation** with a **physician**; each physician sits in one **consulting room** and can practise
several **medical fields**. A consultation moves from `BOOKED` to `CHECKED_IN` and ends `ATTENDED` or
`CANCELLED`. Once a consultation is `ATTENDED`, the physician orders **lab tests** for the outpatient.

## Technologies

- Java 21
- Spring Boot 4 (Spring Web, Spring Data JPA)
- PostgreSQL (tested with version 18)
- Maven (the Maven wrapper `mvnw` is included, so Maven does not need to be installed)

## Project structure

```
src/main/java/com/auca/doctorappointment
├── entity        MedicalField, ConsultingRoom, Physician, Outpatient, Consultation,
│                 ConsultationStatus (enum), LabTest
├── repository    one Spring Data JPA repository per entity (derived queries and @Query JPQL)
├── service       business rules; methods return a List, an Optional or a String message
└── controller    REST endpoints; each message is mapped to an HTTP status with if/else
```

Entities are used directly as request and response bodies (no DTOs). Every id is a `UUID` generated by JPA.

## Steps to run the API

1. **Clone the repository**
   ```bash
   git clone https://github.com/Chris-Shema-1/doctor-appointment-management-system-backend.git
   cd doctor-appointment-management-system-backend
   ```
2. **Create the database user and the database** (in `psql` or pgAdmin, as the `postgres` superuser):
   ```sql
   CREATE ROLE doctor_appointment LOGIN PASSWORD 'your-password';
   CREATE DATABASE doctor_appointment OWNER doctor_appointment;
   ```
3. **Check the connection settings** in `src/main/resources/application.properties`:
   `spring.datasource.username` and `spring.datasource.password` must match the user created above.
   `spring.jpa.hibernate.ddl-auto=update` creates the tables on the first start, and
   `spring.jpa.show-sql=true` prints every SQL query in the console.
4. **Start the application** from the project folder:
   ```bash
   ./mvnw spring-boot:run
   ```
   On Windows (cmd or PowerShell) use `mvnw.cmd spring-boot:run`.
   The API is ready when the console shows `Started DoctorAppointmentApplication`.
5. **Base URL:** `http://localhost:8080/api`

To build a jar instead: `./mvnw package -DskipTests`, then
`java -jar target/doctor-appointment-management-system-0.0.1-SNAPSHOT.jar`.

## Endpoints

All paths start with `http://localhost:8080/api`.

### Part A — CRUD (A2)

The same five endpoints exist for `medical-fields`, `consulting-rooms`, `physicians`, `outpatients` and
`consultations`:

| Method | Path | Success | Error |
|---|---|---|---|
| POST | `/{path}/save` | 201 `Consultation saved successfully` | 404 when a referenced id does not exist |
| GET | `/{path}/all` | 200 list | — |
| GET | `/{path}/{id}` | 200 entity | 404 `The consultation with that id does not exist` |
| PUT | `/{path}/update/{id}` | 200 `Consultation updated successfully` | 404 |
| DELETE | `/{path}/delete/{id}` | 200 `Consultation deleted successfully` | 404 |

(The messages follow the same pattern for every entity: `Medical field saved successfully`,
`The physician with that id does not exist`, ...)

## Testing with Postman

Import `doctor-appointment-management-system-midterm.postman_collection.json` (in the root of this
repository) into Postman. It has one folder per part and one request per requirement, named by its ID
(`A2`, `B1`, `C4`, `D2`, ...), plus the failing cases (404, 400, 409).

- The collection variables (`baseUrl`, `physicianId`, `nationalId`, ...) point at the seed data above.
  On a different database, update the id variables first.

  data is the same afterwards.

  returns `1 consultations cancelled`. A cancelled consultation cannot be changed back, so it gives that
  answer only the first time.
